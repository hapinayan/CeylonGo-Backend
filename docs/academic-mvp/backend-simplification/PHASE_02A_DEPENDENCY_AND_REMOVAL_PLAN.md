# Phase 02A dependency and removal plan

No family is approved for deletion. An out-of-scope feature can have in-scope data or callers. Check both clients and historical transactions before deprecation. Static references below are leads, including comments or matching prefixes. A negative scan does not rule out deployed or dynamic callers. Graph edges represent imports, including function-local and conditional imports. Framework dependencies and handler source lines are in the endpoint CSV. The graph does not prove behavior or reachability of each edge from a particular handler.

| Family | Verdict | Dependency and data impact |
|---|---|---|
| Artisan listings and showcase | BLOCKED | Outside scope. Map catalog and Admin listing workflows need category and visibility checks before unmounting. Preserve uploaded assets and existing foreign keys. |
| Artisan reservations and wishlists | BLOCKED | Outside scope. Inspect the shared provider reservation path, Artisan shared references, booking history, and historical records before separating the router. Validate that map discovery does not consume reservation or favorite state. |
| Advanced promotions and campaigns | BLOCKED | Outside scope. Shared payment callback, discovery and listing behavior, and advanced Admin decisions must be disentangled. Preserve prior transactions, attribution, and campaign state. |
| Sponsorship and advertising | BLOCKED | Outside scope. Shared callback dispatch and financial historical state make removal unsafe before payment reconciliation, Admin scope and approved-publication checks. |
| Advanced analytics | NEEDS REVIEW | Outside scope. Separate reports, earnings and campaign metrics from approved Admin booking visibility and provider booking history. Screen shared dashboard reads, filters and query dependencies. |
| Non-MVP wishlists | NEEDS REVIEW | Standalone wishlist actions are the first plausible batch, but check listing detail flags, composite responses, hidden aliases, client contracts, Admin/map access and shared references. Retain stored rows. |

## Verified high-risk source edges

- [Map catalog](../../../app/services/map_catalog.py) reads multiple catalogs. [Map regression tests](../../../tests/test_interactive_map.py#L268) cover aggregate results and approval flows. Test filtered marker and discovery parity before withdrawing Artisan visibility.
- [Provider reservation service](../../../app/services/provider_reservations.py) and [Artisan reference service](../../../app/services/artisan_shared_reference.py) connect legacy flows to shared history. Move no records during API retirement.
- [Shared PayHere dispatch](../../../app/routers/payments.py#L650) invokes Eco sponsorship and native payment hooks. Gate issuance for the MVP. Callback retirement needs separate finance approval.
- [Activity booking capacity](../../../app/routers/activity_bookings.py#L15) imports Eco and records native events. Choose the canonical Adventure path before deprecating either side.
- [Admin auth](../../../app/routers/admin_auth.py), [shared booking references](../../../app/models/shared.py), and [token version fields](../../../app/models/user.py#L16) are compatibility anchors.
- Frontend and Flutter auth, recovery and provider onboarding paths require contract parity. The CSV includes static references and marks uncertain callers. For every retirement compare route usage with deployed client versions and verify the expected role through dependency and handler tests.
