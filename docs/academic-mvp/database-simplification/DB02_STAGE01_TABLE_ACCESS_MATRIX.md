## Static review and gaps

- [Model/DDL inventory](DB01_EXISTING_SCHEMA_INVENTORY.md) and [dependency matrix](DB01_TABLE_DEPENDENCY_MATRIX.md) contain declared FK/relationship actions and source references for all 99 tables. Runtime tracing includes ORM joins and direct SQL that SQLite actually prepares, including trigger and FK actions when the SQLite fixture enables them.
- SQL Server transaction locks are dialect-specific in [Homestay booking](../../../app/routers/booking.py#L97), [Homestay availability](../../../app/routers/homestay.py#L1362), and [Rental booking](../../../app/routers/rental_bookings.py#L101). Eco's [legacy booking service](../../../app/services/eco_booking_service.py#L763) has additional textual SQL. None of those SQL Server branches were certified by SQLite.
- Startup was disabled. The [booking expiration worker](../../../app/services/booking_expiration.py#L164) reads Homestay bookings with a SQL Server application lock and mutates expiry state through its existing service. The [engine checkout guard](../../../app/core/database_guard.py#L364) is connection identity enforcement. Neither was executed. Weather and Map adapter tasks were reviewed separately from catalog queries.
- [Vehicle approval](../../../app/routers/admin_rentals.py#L411) explicitly requires verified revenue-license and insurance documents for motorized vehicles. Rental role and bike licensing checks remain required. No administrative document write was exercised in this run.
- Native Eco tests and finance Admin regressions are compatibility evidence. They are not proof that those modules belong in the Academic MVP. The mock Eco gateway tests used local fixtures. They neither implement nor verify the approved shared simulated payment contract.
