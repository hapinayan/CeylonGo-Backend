Visibility contract decision, T-06 / P-09

The public vehicle-specific hub route requires an approved vehicle and
returns active hubs owned by its provider. Discovery and booking apply the
broader public_rental predicate, which also checks vehicle availability,
provider eligibility and the active owned default hub when one is assigned.
Product and the API owner need to decide whether direct hub lookup is an
approval-only informational endpoint or must follow the full publication
predicate. They should specify the expected response for an approved
vehicle that fails publication, including HTTP status and whether any hubs
are returned. No shared-hub exception was found in the documented contract.
References: app/routers/rental_vehicles.py:798; app/core/publication.py:103.
The separate legacy provider hub write path accepts active-state changes,
while the map-oriented path uses inactive review. Product and the API
owner still need to decide whether to align those workflows.
References: app/routers/rental_providers.py:1242 and :1274;
app/routers/rental_vehicles.py:100 and :109.
